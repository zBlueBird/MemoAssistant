# Windows 发布合规检查清单

此清单适用于当前 Qt 6.11.1 + MinGW 13.1.0 动态链接发布流程。它不是法律意见。

## 1. 发布前决策

- [ ] 由项目权利人确定 MemoAssistant 自有代码和资源的许可证。
- [ ] 若采用 Qt 商业许可，保存有效许可证明并据此调整第三方声明。
- [ ] 若按 LGPL 3.0 发布，确认下列 LGPL 要求均已落实。

> 当前仓库未声明 MemoAssistant 自有代码许可证。第三方许可证不能替代项目自身许可证。

## 2. 从干净目录生成发行包

从项目根目录运行 README 中的 `scripts/package.ps1`。脚本会清理并重新创建输出目录、运行 Release 构建和 `windeployqt`、复制许可证材料，并生成 `SHA256SUMS.txt`。运行前仍应确认所指定输出目录只包含可删除的历史构建产物。

部署后检查至少包含：

- `MemoAssistant.exe`
- `Qt6Core.dll`、`Qt6Gui.dll`、`Qt6Widgets.dll`、`Qt6Sql.dll`、`Qt6Network.dll`
- `platforms/qwindows.dll`
- `sqldrivers/qsqlite.dll`
- `libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`

仅保留应用实际需要的插件；减少无关插件也能减少额外许可证和攻击面。

## 3. 随包复制第三方材料

把下列文件/目录复制到最终发行包中，并保持文件名与内容不变：

```text
THIRD_PARTY_NOTICES.md
licenses/
```

这些材料包括：

- GNU GPL 3.0（LGPL 3.0 所纳入的许可证正文）
- GNU LGPL 3.0
- GCC Runtime Library Exception 3.1
- MinGW-w64 runtime 与 winpthreads 许可证
- Qt 6.11.1 `qtbase`、`qtsvg` SPDX 清单

## 4. LGPL 动态链接检查

- [ ] Qt 始终以独立 DLL 动态链接；未静态链接进 `MemoAssistant.exe`。
- [ ] Qt DLL 没有被加密、嵌入不可替换容器或受技术措施限制替换。
- [ ] 最终用户可以用兼容的修改版 Qt DLL 替换随包 DLL。
- [ ] 最终用户协议不得禁止 LGPL 所允许的、为调试 Qt 修改而进行的反向工程。
- [ ] 随包提供 LGPL/GPL 完整文本和显著的 Qt 版权/许可证声明。
- [ ] 为所发布 Qt 二进制提供准确的对应源码获取方式，并满足 LGPL 第 4、6 节对“Corresponding Application Code”和“Minimal Corresponding Source”的要求；具体履行方案由发布者/合规负责人确认。
- [ ] 若对 Qt 本身做过修改，保存并按适用条款提供修改后的对应源码与构建信息。

Qt 官方开源义务说明：<https://www.qt.io/licensing/open-source-lgpl-obligations>

## 5. 最终内容审计

- [ ] 对最终 `dist/` 生成文件列表并与 `THIRD_PARTY_NOTICES.md` 对照。
- [ ] 对新增 DLL/插件检查其 SPDX/SBOM 或上游许可，不假定它们都属于 Qt LGPL。
- [ ] 确认发布脚本继续使用 `--no-system-d3d-compiler`，最终包中不包含 `D3Dcompiler_47.dll`。
- [ ] 如果出现 OpenSSL、ICU、FFmpeg、数据库客户端或其他新 DLL，补充相应声明和许可证。
- [ ] 记录用于发布的 Qt、MinGW、CMake、Ninja 版本。
- [ ] 在没有 Qt SDK 和开发环境变量的干净 Windows 11 机器或虚拟机中完成启动、数据库、托盘、提醒和退出测试。
- [ ] 保存发行文件的 SHA-256 校验值和构建日志。
